# Brida machine

Use this whenever the user (Brida creative team) drops a new project/brief, requirements, product photos or video references, or says "запускай машину", "новый батч", "проверь доску", "генерируй кадры". Talk to the user in Russian, plainly; they are not technical.

## Start-up checks (do these first, silently, report only problems)

1. Read the board with the Artifact tool (`action: read`, url below) so later writes/publishes are allowed.
2. Check the Higgsfield connector is usable: `balance` (also tells credits). If it fails, tell the user to enable Higgsfield in this chat's connectors.
   Then the local machine (Bash, desktop app only — see "Local setup"): `BM="$(cat ~/.brida/home)"`, `python3 "$BM/brida_kie.py" credits` (Kie.ai backup) and `python3 "$BM/brida_voice.py" credits` (ElevenLabs). Report balances in one line only if one is low. If `~/.brida/home` is missing or a script fails to start, this Mac is not set up yet — follow "Local setup".
3. ArtifactData `list` of `batches` to see existing batches (avoid duplicate ids/titles).

## Local setup (each team member's Mac)

The team (same Claude account, same Google account) works from two Macs. Everything local is split in two:
- **Shared code** — folder `brida-machine` in Google Drive (`~/Library/CloudStorage/GoogleDrive-<account>/My Drive/brida-machine`), synced to both Macs by the Google Drive desktop app: `kie.py`, `brida_kie.py`, `brida_voice.py`, `setup.sh`, `tools/audio2mp4.swift`, `skill/SKILL.md` (copy of this skill), `README.md`. Below, `$BM` = that folder; its path is in `~/.brida/home`. Code edits go here, so both Macs get them; never put keys, binaries or outputs here. **Touch nothing else in Google Drive**: the rest of My Drive is the user's own files — never list, open, move, rename or delete anything outside `brida-machine`.
- **Personal** — `~/.brida` on each Mac, never synced or shared: `.env` (`KIE_API_KEY`, `ELEVENLABS_API_KEY`), `bin/ffmpeg`, `bin/ffprobe`, `bin/audio2mp4` (built for that Mac), `tools/ffmpeg-skill` (rough-cut tools), `output/` (downloads, VO takes, cuts). Prepend `~/.brida/bin` to `PATH` before using ffmpeg tools.

Setting up a Mac ("запусти установку брида машины", or start-up finds `~/.brida/home` missing): find the folder (`ls -d ~/Library/CloudStorage/GoogleDrive-*/"My Drive"/brida-machine`; if there is none, the Google Drive desktop app is not installed or not signed in to the shared account — tell the user). Run `zsh "$BM/setup.sh"` in a terminal tab the user can see (it asks for the API keys with hidden input — the user pastes them there, never in chat). It builds audio2mp4, downloads ffmpeg/ffprobe (static build from ffmpeg.martin-riedl.de) and ffmpeg-skill (github.com/kajisho5/ffmpeg-skill) into `~/.brida`, writes `~/.brida/home` and prints the balances. Re-running it is safe (updates ffmpeg-skill, fills what is missing).

Two people may work at once on the same board and the same credits: before generating, re-read the review and skip anything whose `voReq.status` is already "working" (someone else is on it); balances are shared — follow the credits rule in "Tone" (name provider and cost; a direct "запускай" is the go-ahead).

## The board (always reuse it, never build a new one)

- Board: https://claude.ai/artifact/VqyuUS7MfBbXvyBVZCiLmu ("Brida Storyboard Board").
- Style guides (source of truth for prompting, team-edited doc): https://claude.ai/code/artifact/c11ca09e-0146-47f4-a807-1be352146eb6 ("Brida — стайлгайды генераций"). If the team edited it since, its rules win over this file; read it when a style question is unclear.
- All content lives in the board's database (ArtifactData tool, `url` = board link):
  - `batches/{batchId}` — one document per project/batch. `batchId` = slug of the title, e.g. `batch-450`.
  - `batches/{batchId}/reviews/{frameId}` — team decisions and media for keyframe K1: `status` (pending|approved|redo|dropped), `prompt` (edited K1 prompt, overrides the batch prompt), `note` (what to redo), `by`, `at`, `image` (board asset id), `gen` ({url, jobId, model} — Higgsfield result), `pulledFrom` (gen url already loaded into `image`), `clip` ({url, jobId, model}), `imageModel` / `videoModel` (per-frame generator override). Extra keyframes live in `kf`: `{"K2": {image, gen, pulledFrom, prompt}, "K3": {...}}` with the same meaning; clips of a chain go in `clips`: `{"K1-K2": {url, jobId, model}, "K2-K3": {...}}`.
- The board itself loads Higgsfield results into the cards, for K1 and every extra keyframe: when a slot has `gen.url` (a Higgsfield cloudfront URL) and no matching `pulledFrom`, the open board downloads it through the viewer's Higgsfield connection and stores it as a board image (automatic once the viewer granted Higgsfield access; otherwise a "Подтянуть на доску" button). So after generating, just write `gen` to the slot. The cloud workspace cannot reach Higgsfield or its CDN; never try to download images yourself.
- Board tabs: **01 Бриф** (the script: exact English VO per frame, the translation in brackets under each line), **02 Раскадровка и промпты** (frame cards: image, short description, editor note, IMAGE prompt, image generator picker, status, Approve/Redo/Drop, redo note with "Отправить правку"; no animation prompt and no video picker here), **03 Кадры** (all frame images in video order), **04 Анимация** (per frame: the animation prompt from `motion`/`motions`, the video generator picker per frame and per batch, clip status), **05 Озвучка** (VO text editing with a length counter, voice picker with search and filters, generator and speed per line and per batch, "Озвучить" queue button, all takes in order with "Выбрать"; see "Voice-over"). The Бриф tab plays the picked take under each line. Also "+ Новый батч", keyframe chains in the cards, angle/cutaway chips, filters, compact view, comments, a ClickUp "Ready for editing" panel, and a "Сборка ролика" view with shot-list export.
- Language switch in the top bar, per viewer: **EN/RU** (default: Russian interface, English VO and prompts, Russian descriptions), **EN** (every label, button, description and prompt in English), **ES** (everything in Spanish, including the VO translation and the image and animation prompts). EN and ES content comes from `batches/{batchId}/i18n/{lang}-{frameId}` docs ({desc, ed, src, angle, tc, k1desc, kdesc[], and for ES also line, prompt, motion/motions, kprompt[]}) plus `{lang}-_batch` ({type, sizes, duration, idea, variations, avatar, hero, narrator, flags[], sections{id:{title, vo}}}). A batch without them shows a "Перевести батч" bar that translates through Claude in small chunks. Translated prompts are display-only: generation always uses the English batch prompt or the review's edited `prompt`. After rewriting a frame on redo, delete that frame's `en-`/`es-` i18n docs so the board offers to retranslate it.
- Do not republish the page to add a project: add a batch document. Republish only to change the board's features (edit the page source; omit `capabilities` on republish so the stored set carries over — db, user{profile}, assets, comments{composer_only}, sample{images}, downloads, mcp{Higgsfield: sandbox_exec; ClickUp: clickup_filter_tasks, clickup_get_task}; always re-read the live page first and patch it, since other sessions edit it too).
- Board update still pending (planned, not built yet): style chip per frame, per-style default generators, Nano Banana 2 / Gemini Omni / Veo 3.1 in the picker, insert templates, auto-adding approved frames to an exemplar library. Until then, write `style` into frames anyway (the board ignores unknown fields) and apply per-style defaults yourself.

```json
 "sections":[{"id":"h1","tag":"HOOK 1","title":"…","time":"0–5s","vo":"…","frames":[
   {"id":"H1A","shot":"MS","style":"ugc_broll","angle":"профиль в движении","cutaway":false,"tc":"0.0–1.8s","line":"exact VO","lineRu":"RU translation of line","desc":"RU what we see","ed":"RU editor note","src":"RU source","ref":false,"prompt":"full EN image prompt (K1)","motion":"EN video prompt"},
   {"id":"B05","shot":"3D","style":"explainer","angle":"3D-разрез","tc":"…","line":"…","desc":"…","ed":"…","src":"…","ref":false,"prompt":"K1 prompt","k1desc":"RU state of K1",
    "keyframes":[{"id":"K2","desc":"RU what changed","prompt":"Same image as the reference: … Change only: …"},{"id":"K3","desc":"…","prompt":"…"}],
    "motions":["EN transition K1→K2","EN transition K2→K3"]}]}]}
```

Sections: one per hook (`h1`,`h2`,… tag `HOOK n`), body `hold` (tag `HOLD 1`), `cta` (tag `CTA`, the offer line). Frame ids H1A/H1B…, B01…, C01. `line` is always the brief's exact VO, never rewritten (a long line split over several frames keeps its exact words, divided between them). Write `lineRu` (Russian translation of `line`) on every frame for the Бриф tab. `motion`/`motions` are shown only on the Анимация tab. Optional fields: `angle`, `cutaway`, `motion`, `k1desc`, `keyframes`, `motions`, `texture` — omit when not used.

`style` (one per frame): `ugc_talk` (UGC, person speaks to camera), `ugc_broll` (UGC, no speech), `pixar`, `stopmotion` (+ `texture`: `clay` | `knit` — one style, only the material words change), `explainer` (3D medical: `glow` variant with particles/colour code, or `anatomy` variant — ivory bones, yellow nerves, blue body silhouette; put the variant in `angle` or `desc`), `insert` (paper sheet, calendar, overlay graphics), `packshot`.

## Storyboard rules (direct response)

**The storyboard is the most important part of every project.** Get it right on the first pass, before any frame is generated:
1. **Learn from the finals first.** Before writing a new storyboard, open the team's FINAL storyboards of the last 2–3 batches on Drive (`My Drive/batches/<batch>/storyboards/…`, e.g. batch 918, 1116, 913) and make a contact sheet. Compare them with what was planned on the board: what the team kept, dropped, replaced and added. Their final selection is the standard, not the board plan.
2. **Pick the format and type from the brief.** Final format (4:5 or 9:16), who leads (doctor VSL / yapper / hero story), and the matching style library (see "Storyboard visual library" and the style templates).
3. **Before showing, check every frame against this list:**
   - one VO phrase = one clear picture that a viewer understands in 1–2 seconds, without the sound;
   - frames 1–2 s, the look changes every 1–3 frames, and no two identical looks or compositions sit side by side;
   - casting fits the type (many different 55–75-year-olds in a doctor VSL; one hero in a hero story);
   - 3D: recognisable body/spine, L4–L5 counted from the sacrum, cells visible, inflammation goes onto the nerve;
   - product: exact label, matches the product ref;
   - nothing unexplained in the frame; the outfit fits the place; people are dressed.
4. When unsure what the team wants for a beat, ask one short question instead of guessing.

### Hooks and "visuals"
- A hook is several fast frames (usually 2–4), about 0–5s total — never one long shot.
- "Visuals" written under a hook in the brief are either a general wish (mood, setting, feeling) or one specific shot that MUST be in the hook. That shot is one frame of the hook, placed where it hits hardest; build the other frames around it. It does not mean the hook consists only of that shot.
- If no visuals are given, invent the hook visuals from the VO.

### Pacing
- No frame on screen longer than 3–4 seconds. A longer VO line is split into 2–3 frames with different angles.
- Exceptions: talking UGC clips and 3D explainers may run longer per scene; explainers only as keyframe scenes (start/end or chains) and may include one cutaway (`cutaway: true`) inside.

### Angles (angle library)
- Never repeat the same angle in two consecutive frames; vary shot size too. Aim for several different angle types per batch.
- Choose the angle that tells the beat best:
  - profile tracking shot for walking; low floor-level for "could barely walk"; high angle down the stairs for stairs;
  - POV from the hero's eyes with the jar in hand and applying the lotion for "started using";
  - POV of the person handing something over (doctor's hand in a white coat holding the bottle in the foreground, the hero opposite filling 70–80% of the frame);
  - object-POV: camera inside a car trunk / cabinet / fridge / bag looking out at the hero, with the edges framing the shot and objects close to the lens for depth (slight wide-angle/fisheye);
  - close-up of hands/feet for symptoms and application; selfie-UGC for testimony lines; over-the-shoulder for everyday moments; macro for product texture; 3D cross-section for mechanism lines.
- Put the angle in `angle` (Russian label) and also describe it in the prompt.
- Start frames show the moment BEFORE the event ("she has not lifted the bag yet", "screws not yet driven in"); the video performs the action.

### Keyframes (start/end and chains)
- Decide per frame how many keyframes the scene needs:
  - 1 = the image is animated as is (use `motion`).
  - 2 = start/end frame: the scene goes from state A to state B (lotion absorbs, person stands up, jar opens, camera flies into the skin, before→after inside one shot).
  - 3+ = a chain of states, e.g. inflamed nerve (K1) → anaesthetic vapour wraps the nerve, redness gone (K2) → cells flare and fire particles, the red inflammation returns (K3).
- K1 is the frame's own `prompt`. Extra keyframes go in `keyframes` (K2, K3, …) with `desc` and `prompt`; `motions` has one transition per pair.
- Every keyframe after K1 is an EDIT of the previous keyframe, never a new picture: its prompt starts with "Same image as the reference: identical camera angle, framing, composition, anatomy and lighting. Change only:" + the change. The camera never moves between keyframes; only the state changes.
- Exception — deliberate camera moves: when the team asks for one shot that goes from one place to another (camera pulls back from the spine to the hero in the bathroom; flies from the room into the back), K2 is a different picture and the motion prompt describes the camera move. Several consecutive frames may also be merged into one clip (e.g. B18 → B18.1 → B19 as one start→end chain); note it in `ed` of each merged frame and store the clip on the first one.
- Kling 3.0 Omni takes only start + end (no middle keyframe). For a 3-state scene either make two clips (K1→K2, K2→K3) or drop the middle state.

## Prompt writing (from the team's liked generations)

### General rules for every prompt
1. **Image first, then video.** Every clip is made from a generated frame (start, often start+end). Do not write text-to-video.
2. **Edit or regenerate — decide per frame.** Edit an existing frame ("Keep the same [person], same outfit, same [room], same camera angle and same lighting. Change only: …") when it is the same shot with a small change: start/end keyframes of one scene, a fix of one detail, a new angle of the same scene ("…Change the camera angle completely. The camera is now …"). Generate fresh with a full prompt when the scene, room, outfit or composition is new, or when edits keep dragging old mistakes along — the team often prefers fresh frames ("лучше заново генерируй"). Fresh frames still hold identity and look through references: hero ref (+ outfit ref) + the batch's style refs.
3. **Label every reference's role**: "Use Image 1 as the exact reference for the man (face, hair, body). Use Image 2 only as a reference for how close the camera is. Do NOT copy the room, pose or clothing from Image 2."
4. **Long sectioned prompts**, CAPS headers. Live action: `CONTEXT — / REFERENCE — / SHOT — / SUBJECT — / ACTION — / PERFORMANCE — / PHOTOGRAPHY — / AUDIO — / NEGATIVE —`. 3D: `SCENE — / ACTION — / CAMERA — / CRITICAL — / STYLE — / NEGATIVE —`. 1,500–3,000 characters is normal; talking heads longer.
5. **Camera physics in words**, never "UGC style": "The phone has been placed on the floor at the bottom of the staircase, nobody touches it" OR "Raw handheld phone footage with NO stabilization: subtle hand shake, breathing sway, small accidental tilts, minor reframing corrections. No tripod, gimbal, zoom, push-in, orbit." Camera moves are physical ("moves physically closer… no digital zoom").
6. **Sharp focus everywhere** for UGC and Pixar: "Everything in the frame is equally sharp and in focus. Deep depth of field, no bokeh, no background blur, no shallow-focus or cinematic look." For Pixar: "no heavy background blur; keep the room readable". NEVER write "shallow depth of field", "background softly blurred", "bokeh" outside explainers/packshots — that is what blurred the team's Pixar frames.
7. **Restrained acting**: doesn't look at or perform for the camera (except talking clips), uneven human steps with pauses, "no dramatic stumbling", elderly move "NOT quick and bouncy like a 20-year-old".
8. **Counts and exclusives repeated** 3–4 times: "exactly 2 screws… strictly only 2… no extra screws".
9. **Size and priority as numbers/lists**: "she occupies 70–80% of the frame"; "focus: 1. the hand with the bottle 2. the woman".
10. **Product lock**: label facing camera and readable, full label text, the jar never spins/floats/looks pasted, fingers don't cover the brand, "nothing else on the table". No glowing watches, no rings.
11. **Long NEGATIVE** every time: text/subtitles/captions, music, cuts, zoom, extra fingers/toes, outfit/face/room changes, morphing.
12. **Style refs on every frame.** When a batch has style references (e.g. 5 frames from a liked film/ad), attach ALL of them to EVERY image generation — K1, edits, 3D scenes — labelled "STYLE references ONLY… copy nothing else from them". Frames got visibly weaker without them. Max 7 refs per Nano Banana generation, so hero/scene refs + style refs ≤ 7.
13. **Outfit fits the scene.** Write an explicit OUTFIT line in every prompt with the hero. Street clothes outside, home clothes at home (nobody washes dishes in a vest and sneakers), sportswear at physical therapy, a patient gown at the clinic, slippers or barefoot in bed/at home, nightwear at night. Face, hair, glasses never change. When the outfit differs from the hero ref: "use Image 1 only for face and hair, ignore its outfit". Keep a fixed outfit set per batch (street/home/garden/sport/clinic/night) and reuse it.
14. **Colour contrast.** Name the wall/curtain/furniture colours AND an outfit colour that clearly contrasts with them and with the hero's hair (never a beige cardigan in a beige room). Vary room palettes between scenes.
15. **Modest, readable poses** for elderly heroes: no reclining "posing", no odd skin marks (an antiseptic circle reads as a stain). Walking: along the path in a clean profile, never drifting towards a road; on screen motion runs horizontally.

### Style templates

**UGC frame (image).** Nano Banana 2 (Pro as fallback), 9:16, 2K. Order: reference roles → scene → pose (anatomical: which hand where, toes curled, "brows deeply furrowed, eyes squinted, lips pulled back"; gaze "NOT looking at the camera… looking at his own feet") → camera → light → AVOID. Lines to include: "Shot on an ordinary phone camera, handheld, slightly imperfect framing, from a normal standing height." "Realistic amateur snapshot with fine natural texture and slight phone-camera noise." "NOT professional photography, NOT DSLR, NOT studio lighting… camera tilted a few degrees." "The whole frame is bright and open, no dark corners, no vignette." + sharp-focus line. Avoid: face/hand/feet distortion, feet cut off, text, extra people.

**UGC b-roll (video, no speech).** Gemini Omni 3s or Gemini Omni Flash 1.1 3–7s (Kling 3.0 ok). ~330–430 words. Start with "No subtitles. No music." then CONTEXT ("Everyday home-health documentary clip showing… Fully clothed subject, non-sexual, realistic observational tone.") / REFERENCE ("Use the uploaded frame as a strict visual reference for [list everything]… Preserve all visual details.") / SHOT (one of the two camera modes above) / SUBJECT / ACTION (uneven human steps: "firm pressure, a brief pause after hitting a sensitive spot, then another attempt") / PERFORMANCE ("never looks at the camera, never speaks, never performs for the viewer, restrained winces") / PHOTOGRAPHY ("Authentic consumer-phone image, ordinary natural daylight, wide depth of field, everything in focus, natural skin texture, mild sensor noise, no bokeh, no cinematic grading, real-time speed.") / AUDIO ("No dialogue. Quiet room tone, soft clothing rustle, restrained uneven breathing.") / NEGATIVE.

**UGC talking (video with speech).** Gemini Omni Flash 1.1 or Veo 3.1 (Seedance 2.5 for 7–15s). Delivery must be fast: 3–4 words per second (normal speech is 2.3–2.5). Tricks: state a longer duration than the clip ("completing the sentence within approximately 5–6 seconds" for a 4s clip), or for long clips "DO NOT stretch the dialogue to fill all 10 seconds… he finishes early and stays naturally on camera". Structure: person lock → jar/hand lock → `# HIGHEST PRIORITY — VERY FAST, SHARP, REALISTIC DELIVERY` → `# EXACT SPOKEN DIALOGUE` → `# SPEED TARGET` → phrase breakdown → `# INTONATION MAP` → micro-movements → `# MOUTH / LIP SYNC` → `# ABSOLUTE ZERO CUTS` → `# CAMERA` → `# FINAL DELIVERY CHECK` (repeat the line). Repeat the line 2–4 times. Line: first person, conversational, numbers as words, drug names phonetically ("GAB-uh-PEN-tin"), pauses in ms ("~300-millisecond breath after 'meds'"). Must-have lines: "He speaks VERY FAST and sharply for realism. FAST DOES NOT MEAN MUMBLED. FAST DOES NOT MEAN ROBOTIC." "Speech starts immediately at 0:00. No intro silence. No preparatory inhale." "DO NOT slow down for the medical terminology." "Use only a clean, natural American accent. No British, Australian, Irish or foreign accent." "Not a comedian, not a polished commercial actor, not a salesman. No broad advertising smile." "This is NOT voice-over… his own mouth must visibly produce every word." "No micro-cuts. No lip-sync restart. Punctuation must NEVER create a new shot." One gesture per clip on a specific word; free hand hangs naturally. Negative FIRST: no subtitles/captions (Veo burns them in), no music, no stutter/repeated words, no robotic voice, jar doesn't switch hands. For Gemini Omni Flash 1.1 the "state a longer duration" tricks do NOT work. It stretches speech to fill the clip, so use the doctor talking-head rules below instead.

**Pixar.** Images on Nano Banana 2/Pro; talking character (e.g. the nerve creature) on Kling 3.0 pro with sound, 7–8s, ~2.7 words/s; short scenes with people on Gemini Omni Flash 1.1 or Kling 3–5s. Order: style lock ("polished 3D Pixar/Disney-style animated render — stylized cartoon animation, NOT photorealistic, NOT live action") → character lock ("keep the exact same red cartoon nerve creature… no morphing") → gaze ("looks STRAIGHT INTO THE CAMERA LENS for the entire shot" when talking) → line + voice ("finishing the whole sentence completely before the clip ends") → actions tied to words ("On the word 'gabapentin,' a capsule drops…") → camera ("static camera, subtle motion" or one slow push-in) → negatives. Human scenes: camera & composition / character (identity list: "silver-gray bob, glasses, small earrings"; outfit changes stated explicitly "outdoor clothes, not pajamas") / pose / effect strictly localized ("ONLY on her lower back… NO skull, NO rib cage") / environment / lighting. Palette: "premium Pixar-inspired 3D render, rich multicolor palette, objects of different sizes, bright but warm colors, no sepia filter, subtle cool blue tones in the shadows, global illumination, ambient occlusion" + "no heavy background blur; keep the room readable". Unusual angles + slight fisheye work well here (POV doctor, inside the trunk). Negative: unfinished line, swallowed last word, looking away, shape change, photorealism, comedy, horror, gore, flat 2D overlays.

**Stop-motion (`texture` clay or knit).** The most-liked style. Kling 3.0 pro, sound OFF, 3–4s (5–6s for several actions), start frame; transformations start+end. Template: "Use the uploaded image as the exact START FRAME. Preserve the same [elderly woman clay puppet], [all objects], warm lighting, camera angle, and vertical 9:16 composition. Keep all key action inside the 4:5 safe zone." → "This must look like true handcrafted clay stop-motion, not smooth AI video. Animate frame-by-frame at around 10–12 fps. Movement must feel stepped, slightly choppy, and handmade, with small pose-to-pose increments, brief hold frames, and visible puppet timing." → "One continuous shot with a locked static camera. No cuts, zoom, reframing, or scene change." → one simple action in steps (First… Then… After a brief hold…) + micro-acting ("one soft blink, a tiny head tilt, slight breathing") → pain effect (lightning anchored to one spot, "never disappear, never respawn, never fly away", only moves up/down) → "Preserve tactile clay textures, fingerprints, handmade imperfections, miniature-set depth, and practical puppet animation logic." → `Hard constraints:` one sentence ending "…no lip sync, and no smooth motion". Harder clay: "Hard handmade plasticine stop-motion… Matte clay surfaces with fingerprints, dents, uneven edges, small deformations, subtle micro-cracks. No smooth CGI." Knit: same template, "practical puppet shot… tactile knitted textures, visible yarn stitches". Characters never speak; objects never vanish or reappear; emotions "restrained, sincere, not exaggerated or comedic"; after relief list the absence ("No red glow, no lightning, no limping").

**Pixar medical explainer (cartoon villain cells, see-through body).** Proven in BATCH#913 (spinal stenosis, mast cells):
- Villain cells: one fixed cartoon design per batch (ref image), grinning, mischievous, "cartoon-playful, not scary". In clips they MOVE: hover and drift around the nerve at a moderate pace, stay inside the frame, throw small red-orange sparks, little puffs of inflammation that drift and fade. NO big red cloud or fog, no flashes, no cells flying out of frame, and the spine/discs NEVER move. Reference motion prompt: "CAMERA — very slow push-in toward the pinched spot. ACTION — the inflamed nerve throbs red and hot at the pinch, pulsing like a heartbeat; the grinning mast cells keep throwing red-orange sparks at it, little bursts of inflammation puff around the pinch, sparks drift and fade." (gold-standard clip: Higgsfield job 8865c2ce-590b-478c-b999-da933410a0ce).
- See-through spine on the hero: the hero is shown as a normal Pixar person, the spine simply SHOWS THROUGH the body/clothes (glowing x-ray look), anatomically placed and straight, with one hot red spot at L4–L5 and tiny mast cells there. No cut-out window in the clothes, no crooked spine. Remove bulky outer layers (vest) in such frames.
- Anatomy: lumbar stenosis side view = ONE long yellow nerve cord inside the canal behind the vertebral bodies, pinched at L4–L5 (disc from the front, ligament from the back); no yellow nerves sticking out sideways. Back view: straight column, muscles on both sides.
- Variety: 3D frames must not repeat one illustration. Change camera (top-down slice, inside the canal tunnel, worm's-eye at cell level, back view, 3/4 cutaway, close side view) and background colour (amber, violet, peach, plum) per frame; don't attach the same anatomy ref to every 3D frame — describe anatomy in words.
- Make the VO line readable in one picture: show both halves of a contrast together (e.g. "That's good. But it does nothing for the mast cells" → strong green-glowing back muscles in front, cells behind them still inflaming the red nerve, one cell mocking with a tiny dumbbell). Colour code: green glow = strengthened/healthy, red = inflamed, golden = product/PEA.
- When the team asks for options ("2–3 варианта, на доску не ставь"), generate them off-board, show them, and put on the board only the chosen one.

**3D explainer.** Video on Gemini Omni (4s) or Gemini Omni Flash 1.1 (~6s), start+end (sometimes a middle keyframe). Opening: "Use the uploaded START and END frames as strict references. Begin with the exact [state] from the START frame and finish with the exact [state] from the END frame. **Doctor talking head (doctor Q&A ads, proven in BATCH#1153).** One doctor answers a viewer comment to the phone camera. The team gave this feedback many times; follow all of it:
- **Model:** Gemini Omni Flash 1.1, 720p, sound on (Higgsfield, or Kie when Higgsfield is low). One take per line unless the team asks for variants ("по две попытке не надо").
- **Maximum speaking speed, ALWAYS, on every clip**, without being reminded. The model stretches speech to fill the whole clip and tops out near 3.7–4.1 words/s. Speed therefore comes from the DURATION: the clip must be just long enough for the line, ≈ words / 3.8 s, rounded to the nearest allowed length, never generously up. Higgsfield takes any whole 3–10 s; Kie only 4/6/8/10, so on Kie pick the shorter option when it still fits (21–22 words → 6 s worked at 3.8–4.1 w/s). Too short and the last word is cut off, which also fails ("недоговорил"). Longer clips (8 s for 22 words) come out slow (~2.9 w/s) and the team rejects them.
- **NEVER speed up, trim or otherwise edit clips with ffmpeg.** Post-processing is the editor's job ("не надо ничего ускорять самому"). Only download, measure and report.
- **After every clip, measure and report:** speech start–end and tail with `ffmpeg silencedetect` (n=-35dB:d=0.15), words per second, and a contact sheet of frames. Flag a tail under ~0.2 s as "последнее слово может быть съедено". Say honestly that the words were not checked by ear.
- **Prompt order:** `# NEGATIVE FIRST - CLEAN FRAME` (no subtitles/captions/burned-in text/new words; only writing already in the image — whiteboard, certificates, product label — stays unchanged; "the spoken words exist ONLY in the audio track") → `# HIGHEST PRIORITY - MAXIMUM SPEAKING SPEED` ("AS FAST AS A PERSON CAN TALK while staying clear, about 4.5 words per second… NO pauses between sentences… Speech starts on the VERY FIRST FRAME… said to the very last word") → `# SPOKEN LINE (audio only, never shown as text)` with the line WITHOUT quotes → `# TIMING` ("The whole line is done by about X seconds. Then he stops talking… settles back into the exact start pose") → `# START FRAME = END FRAME` → `# PERSON LOCK` → `# PERFORMANCE` (looks straight into the lens, not a salesman) → `# VOICE` (exact words, no stutter) → `# CAMERA / AUDIO` → `# FINAL CHECK` (repeat: no text, full line, exact start pose). A quoted line under "EXACT SPOKEN DIALOGUE" made Gemini burn in subtitles.
- **Seamless cuts:** pass the SAME avatar image as `start_image` AND `end_image` on every talking clip, so the hands and pose match at each cut. When the product is in hand, use the "doctor holding the bottle" image as both start and end.
- **Product pickup clip** (start = avatar without the bottle, end = the same doctor holding it): describe a natural reach step by step with times. He looks down toward the desk corner, leans slightly, his hand goes out of frame, he grabs the bottle while watching his hand, and the bottle ENTERS THE FRAME FROM THE BOTTOM EDGE already gripped, while his eyes return to the lens. Add a BOTTLE LOCK block: one rigid bottle, sharp in every frame even in motion, never fades in, never forms or floats in mid-air. Without that, the bottle "materialised" in the air. A natural reach needs about 8 s, so this clip ends up slower; say so.
- **Hooks:** the doctor reads the viewer's comment aloud from his phone (start = end = the image of him looking at the phone). He reads at maximum speed, eyes on the phone the whole time; no comment bubble or text in the video. The comment bubbles are separate images (below).
- **Comment bubbles for the edit:** Nano Banana 2.1 (Kie, 2K, 9:16) with the team's example as Image 1: flat chroma-key green (#16E516), a white TikTok-style "Reply to comment" bubble in the upper left with a small round avatar, and the comment EXACTLY as in the brief ("??", emoji). A different asker each time: real-looking 55–75-year-olds, both men and women. Check the spelling in each result.
- **Script lines:** speak them exactly, numbers as words ("six hundred milligrams", "ninety day", "four in ten"), abbreviations spelled out ("P-E-A", "M-R-I"), drug names phonetic ("GAB-uh-PEN-tin"). Fix an obvious typo only so it is speakable ("That's combination" → "That combination") and tell the team.
- **Splitting the hold:** one clip per sentence or two (12–25 words). The team may later ask to merge lines into one longer clip; then keep the same duration rule.
- Higgsfield sometimes flags a plain medical line as NSFW. Retry once with "a friendly American doctor answering a viewer's health question"; a flagged job is normally not charged.
- **Files:** `~/Downloads/BATCH-<n>/hold-clips/…`, `…/hooks/`, `…/hooks/bubbles/`. The team marks rejects by renaming files ("3 переделать"), so look in the folder before redoing.

**Doctor Q&A b-rolls and pop-ups (spinal stenosis).** No inserts with people: the doctor is the only person. B-rolls are 3D only, with start + end keyframes (often 3+). Pop-ups are plain still images: icons, photos, a pill bottle, a calendar, a badge. Anatomy is always classic L4–L5 lumbar stenosis, mast cells around the pinched nerve in the canal, never in bone. **UGC hero talking head (the "yapper", proven in BATCH#1116).** An ordinary 60s person telling their own story to the phone's front camera; the whole script (hooks, hold, CTA) is cut into talking clips and the b-rolls go on top in the edit. Unlike the doctor, the team wants a NATURAL pace here, not maximum speed:
- **Model:** Gemini Omni Flash 1.1, 720p, sound on, start = end = the avatar image the user sends (in the chat or `storyboards/avatars`). On Kie only 4/6/8/10 s exist.
- **Pace:** about 3.2–3.5 words per second of clip, e.g. 32 words in 10 s, 26 in 8 s, 19 in 6 s, 13 in 4 s. 4.4–5.2 w/s ("as fast as a person can talk") and even ~4.1 w/s were rejected: "слишком быстро, люди так не говорят". Put LESS text into the same duration rather than more seconds; more clips per section is fine. Split only at sentence ends.
- **Prompt blocks** (same clean-frame order as the doctor template): `# HIGHEST PRIORITY - CALM, NATURAL CONVERSATIONAL PACE` ("about 3.3 words per second… relaxed and fluent, NOT rushed, NOT rapid-fire… also not slow or sleepy… natural short breaths between sentences") → `# SPOKEN LINE` (unquoted) → `# PAUSES - CRITICAL` (each sentence in ONE unbroken breath, a short breath only at a full stop, no stumbling) → `# INTONATION MAP` (per sentence: its mood and which words get the stress) → `# TIMING` → `# START FRAME = END FRAME` → `# PERSON LOCK` → `# PERFORMANCE` → `# VOICE` → `# CAMERA / AUDIO` → `# FINAL CHECK`.
- **Known failures and fixes:** a pause in the middle of a sentence, usually at a comma → remove that comma from the spoken line (the words stay) and/or give less slack time. A long gap between two sentences that the model will not shorten → split into one-sentence clips (`H21a`, `H21b`). Flat, rattled-off delivery → add the intonation map. A stumble → just rerun. Burned-in subtitles → rerun at once (it happened once in ~30 clips).
- **Files and names:** `~/Downloads/BATCH-<n>/hooks/` and `…/hold-clips/<version>/`, clip names `H01…`, `H03a/H03b` for split lines, CTA as `C01…`. When the user keeps some clips and asks to redo others, write the redo over the old file with the same name.
- Cost on Kie: ~14 credits per second (84 for 6 s, 126 for 10 s).

### Storyboard visual library (doctor-led VSL, from the FINAL BATCH#918 storyboard on Drive)

## Doctor-led VSL (proven in BATCH#918 "If I Wanted To Relieve SS", Nov 2026)

A long VSL (hooks 1–3 + ~90-frame hold) narrated by a doctor, lumbar stenosis + mast cells, product PEA (Nerve Breakthrough). Format of the final video: **4:5**. Storyboard on the board, then the user's own selection on Drive, then animation frame by frame.

**Storyboard**
- The doctor appears RARELY (brief: "show the doctor from time to time… really dynamic"; the reference cuts every ~1.9 s, doctor on screen ~15–20%). Almost every VO phrase gets its own insert/b-roll of 1–2 s; full-screen doctor only on a few authority beats ("Look", "The solution?", "I recommend", "I need to warn you"), elsewhere at most a corner circle.
- **3D explainers:** default to a 3D GLASS look (translucent body/anatomy, glowing inner nerve). Rules the user set "на будущее":
  1. Nothing unexplained in the frame: no stray or background nerves/spines that the story doesn't need.
  2. Neighbouring 3D frames differ in angle, colour AND style; never repeat a composition already used in the batch. "3 варианта" = 3 different styles, never 3 runs of one prompt. Before generating, list the looks already used nearby.
  3. Styles only from the user's reference library: semi-transparent skin/muscle layers on light blue; glowing blue x-ray nervous system on black; realistic skin with a textbook cutaway; stylized white-shirt overlay with glowing organs. A free-floating studio spine on a gradient ("pharma MOA") was rejected even after "любой стиль на твой вкус".
  4. Anatomy always inside a recognisable spine/body; no context-free macro of a nerve + disc ("максимально непонятно — это стеноз?"). Never an axial (top-down) slice, "раз и навсегда". Textbook sagittal stenosis: bodies + discs in front, canal behind, disc bulges back + ligament forward at L4–L5 only.
  5. **L4–L5 check, every time.** Nano Banana drops a disc or puts the red glow one level too high. List elements top to bottom in the prompt (L3, L3–L4 disc, L4, L4–L5 disc = pinch, L5, L5–S1 disc, sacrum, "exactly 3 discs"), then crop the lumbar area at full resolution and count discs up from the sacrum before showing. Fix that worked: "move the whole red glow DOWN by exactly one vertebra… the lowest disc (on the sacrum) stays blue; the disc directly above it glows red, at the level of the top rim of the hip bone".
  6. Mast cells clearly visible (about as wide as the nerve is thick). Inflammation always flies FROM the cells ONTO the nerve, never away.
  7. Concrete literal metaphors beat abstract glows (a stream of red blood cells hitting the nerve, not "warm light along capillaries").
  8. Translucent/silhouette people always dressed (Nano Banana draws them nude); no bare buttocks — add trousers.
  9. Supplement bottles may carry a neutral name ("PEA / 300 mg"), never a real competitor; reuse the first bottle as a ref so it stays the same.
- Save every chosen frame's 2K original (Kie PNG) to `~/Downloads/BATCH-<n>/originals-2K/b<n>-<ID>_K1.png` right away; the scratchpad/tmp gets wiped and Kie links expire.

**Drive layout (the user's selection and the deliverable)**
- `batch <n>/storyboards/{hook 1, hook 2, hook 3, hold}`: the user's final frames in edit order; notes in file names are tasks ("42 ниже позвонок", "52 больше пеа", "85 банку исправить", "51 сделать крупный план"); `N\1 на выбор` = alternatives. `stuff со старым форматом` = the old 9:16 frames, do not use.
- `batch <n>/video/{4x5, 9x16}/{hook 1, hook 2, hook 3, hold, doctor}`: the finished clips, sorted by the user's request, named by frame number: `12.mp4`; two frames in one clip `34-35`; alternative frame `10_1`; redo `11 v2` (keep v1 unless told "удали старый"); hooks with take letters (`01 V1`, `05 G1`, `07 K1 kling`). Gemini clips go into both folders (9x16 original + 4x5 crop); Kling clips only into 4x5. Old versions "удалить" = move to the Mac Trash, not hard delete.
- Before saying "всё загружено", walk the storyboard list against the video folder and name every frame without a clip (doctor frames are covered by the doctor clips).

**Animation (Gemini Omni Flash 1.2, 1080p, 9:16 → crop 4:5; Kling O3 when asked)**
- Two images for one frame: the user decides "start + end" or "просто вставь обе картинки" (refs). If they didn't say, ask; refs mode on Gemini gave freer, more natural motion; start/end is for exact end poses.
- Overlays (x-ray, red glow, green glow) must stay to the last frame: "the x-ray overlay and RED glow stay visible for the WHOLE video, never fading". Gemini still drops them sometimes; check strips and say so.
- Mast cells inflaming the nerve (from the user's reference): "the cell membrane tears open on the nerve side, a dense stream of small red granules pours onto the nerve, forming a pinkish-red cloud; granules go ONLY onto the nerve". Small round particles, not sparks.
- Name exactly WHICH element pulses ("only the nerve pulses; the disc stays still"); a pulsing disc was rejected.
- An effect spreading where it must not (golden pulses below the knees) that no prompt fixes: freeze that region with an overlay of the first frame (crop + alpha gradient `geq … a='if(lt(Y,90),255*Y/90,255)'`) over the clip.
- Start and end frames with different zoom make the camera jump: generate a matching wide start from the end frame (edit "same scene, camera further back"), then Kling start/end works.
- Simple precise actions (a hand draws a line in one calendar square) → Kling O3 start/end. Dramatic live-action hooks on Kling (fall, crunch, scream) were rejected as "ужас" → Gemini.
- Kling prompts: short, step by step ("First… Then…"), plus a Negative list; it ignores long prose.
